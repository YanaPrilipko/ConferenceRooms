# ConferenceRooms API

Коротка документація проєкту з описом бізнес-завдань і технічних рішень.

## 1) Бізнес-завдання

Система потрібна для автоматизації керування конференц-залами:

- вести каталог залів (назва, місткість, базова погодинна ставка, додаткові сервіси);
- бронювати зали на конкретний часовий інтервал;
- уникати подвійного бронювання в один і той самий час;
- розраховувати вартість бронювання (оренда + вибрані сервіси);
- аналізувати завантаженість залів за період.

## 2) Основні сценарії

- Адміністратор створює/оновлює/видаляє зали.
- Користувач шукає доступні зали за часом і місткістю.
- Користувач створює бронювання з опційними сервісами.
- Керівник отримує звіт по завантаженості залів.

## 3) Технічні рішення

- Платформа: `.NET 8`, `ASP.NET Core Web API`.
- Доступ до даних: `Entity Framework Core 8` + `PostgreSQL` (`Npgsql`).
- Документація API: `Swagger` (`Swashbuckle.AspNetCore`).
- Архітектура: контролери + сервісний шар (`IConferenceRoomService`, `IRoomReportsService`) + шар даних (`ConferenceRoomsDbContext`).
- Валідація: Data Annotations у DTO + бізнес-перевірки в сервісах.
- Rate limiting: глобальне обмеження `100` запитів/хв.
- Обробка помилок: централізований `ExceptionHandler` та стандартизовані коди помилок через `OperationResult`.

## 4) Ключова бізнес-логіка

- Перевірка конфлікту бронювання: перетин інтервалів часу для однієї кімнати.
- Розрахунок вартості: базова погодинна ставка * тривалість + сума сервісів.
- Звіт завантаженості: обчислення частки заброньованих годин у вибраному періоді.

## 5) API (коротко)

### Rooms
- `GET /api/rooms` — список залів.
- `POST /api/rooms` — створення залу.
- `PUT /api/rooms/{id}` — оновлення залу.
- `DELETE /api/rooms/{id}` — видалення залу.
- `GET /api/rooms/available` — пошук доступних залів (`start`, `end`, `capacity`).

### Bookings
- `POST /api/bookings` — створення бронювання.

### Reports
- `GET /api/reports/room-utilization` — звіт завантаженості (`from`, `to`).

## 6) Конфігурація та запуск

- Рядок підключення: `ConferenceRooms/appsettings.json` ? `ConnectionStrings:ConferenceRoomsDb`.
- Запуск: `dotnet run --project ConferenceRooms/ConferenceRooms.csproj`.
- Swagger у Development: `http://localhost:5000/swagger` або `https://localhost:7148/swagger`.

## 7) Висновок

Проєкт закриває ключові потреби керування конференц-залами: оперативне бронювання без конфліктів, прозорий розрахунок вартості та звітність для прийняття рішень.
